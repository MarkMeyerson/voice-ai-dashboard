## Fix soon (medium)

| 6 | `message_basis = 'all'` double-counts user turns: `chatToRow` stores agent plus user in `message_count`, then `usage.ts` adds `user_message_count` again. Not hit today (WFWC is `'agent'`), but the setting is one click away in the form. | Store `message_count` as agent turns always; derive the metered figure in one helper used by `chatToRow`, `usage.ts`, `metering.ts`. |

| 8 | **Decision needed.** Dashboard month is the Chicago calendar month; Stripe's 2,000-message allowance resets on the subscription anniversary (the day the payment method is added). | 11 | Row caps truncate billing math: portal reads 500 calls, admin pages hit PostgREST's 1,000-row default with no warning. Fine today (68 rows total), wrong at scale. | Aggregate per client per period in SQL (view or RPC); paginate the call log. |

Fine at WFWC's volume; at 200 chats a day it is ~200 Retell GETs per run and ongoing chats past the cap never get their final count. | Only `getChat` ids that are new or still `ongoing`; paginate list-chats; bounded concurrency. |

| 14 | Editing a pod's rate or plan updates the database but never Stripe; invoices keep the old prices. | On billing-field change with a subscription, create new prices and swap the subscription items, or refuse the edit with a message. |

## Low

- Open redirect in `/auth/confirm` (`next` accepts absolute URLs). Require a leading `/`.
- Retell signature has no timestamp window; a captured delivery replays and re-sends the summary email because `email_sent_at` is written but never read on the webhook path.
- Stripe webhook has no event-id idempotency; two concurrent `checkout.session.completed` deliveries could create two subscriptions.
- Client Refresh button is an unthrottled Retell fan-out (list plus up to 100 get-chat calls per click).
- No Content-Security-Policy header (HSTS, nosniff, frame deny are present).
- Dependencies: `npm audit` reports 8 advisories (1 critical, 5 high) all in transitive packages (`sharp`, `source-map-js`, `qs`); `npm audit fix` clears most, the `sharp` one needs Next 16.4. Top-level packages are behind: next 16.2.6 (16.4.2), stripe 22.2 (23.0), retell-sdk 5.32 (6.2), @supabase/ssr 0.10 (0.12). Lint has 2 pre-existing errors and is not enforced in CI.

## Documentation and structure drift

- CLAUDE.md and README still say the Retell webhook is lenient and to "re-enable the 401"; the code already returns 401.
- Architecture map omits `api/cron/reconcile`, `lib/drive.ts`, `lib/metering.ts`, `lib/usage.ts`; README says 5 tables (6 with `pod_agents`).
- `.env.example` lacks `CRON_SECRET`, `ADMIN_SUMMARY_EMAIL`, `DEMO_REQUEST_EMAIL`, `STRIPE_CHAT_METER_EVENT`.
- `drive.ts` and `drive_folder_id` are Supabase Storage, not Google Drive; `googleapis` is a dependency with zero imports.
- Duplicated logic: the list-calls-and-upsert block exists in three places, the summary-email block four times, `money()` in six files; `isChatRow` and `isChatType` differ.
- Dead code: `sendWelcomeEmail`, `setAgentWebhook`, `retellClient`, `getDefaultPaymentMethod`; `forgot-password/actions.ts` returns the same result on both branches.
- Cron alert text says "daily reconciliation" but it runs every 15 minutes; the `appUrl` fallback differs between webhook and cron.

## Done well

Tenant reads go through the cookie-bound RLS client and the service-role client never reaches a client component. Every admin page and action calls `requireAdmin()`. Stripe webhook verifies the raw body; Retell HMAC uses a constant-time compare. `retell_call_id` and `stripe_meter_event_id` are unique, so ingestion is idempotent. Money is integer cents throughout. Security headers are set. CI type-checks every push.
